# Chrome HTTP 下载与连续 PDF 下载

先按[浏览器选择](browser.md)优先通过 Codex Chrome 插件（`@Chrome`）操作用户本地 Chrome；插件不可用或无法连接同一会话时，再使用可用的 Chrome DevTools MCP。连接、下载收据和权限操作遵循当前工具说明；Chrome 内部设置页面是否可操作以工具实际能力为准。校园下载来源与文件核验仍须逐项确认。

本页权限准备是 [校园访问与认证](access.md) 中的环境检查步骤；权限准备和机构认证完成后，再使用 [下载工作流](workflows/download.md)。以下规则优先于原工作流中的批量下载建议：本适配版默认逐篇串行下载；用户明确要求原生批量且已确认文件格式、数量及权限时才使用该批量入口。

## 允许校园 HTTP 下载

这项操作前移到联网任务的环境检查阶段，在检索和下载前完成，不以已经发生HTTP拦截为前提。默认按用户选择的校园通配规则 `[*.]htu.edu.cn` 检查“允许显示不安全内容”列表，具体步骤见下节；只处理精确来源时按下列站点步骤核实。更改安全相关权限仍遵守当前工具的确认要求，已授权的同一操作不重复询问。工具无法操作设置页时，先指导用户完成并记录确认；不能仅因脚本执行成功就声称浏览器设置完成。

1. 打开页面地址旁的站点信息 → 网站设置，核对站点是 `http://www-cnki-net-s.vpn.htu.edu.cn:8118` 或任务中实际观察到的校园知网来源。校园代理会按资源类型分发到不同子域，见下方“实测下载链路”；只给首页来源放行通常不覆盖真正的下载来源。
2. 将该站点的“不安全内容 / Insecure content”设为“允许”。需要连续下载时，将该站点的“自动下载 / Automatic downloads”设为“允许”。这两项权限分别处理 HTTP 内容和多文件请求，不能互相替代。
3. 可通过 `chrome://settings/content/insecureContent` 和 `chrome://settings/content/automaticDownloads` 查看具体站点例外，但控件名称、可访问性以当前 Chrome 为准。默认只添加精确来源，不关闭 Safe Browsing，不修改注册表或运行中的 Chrome 配置文件。
4. 重新观察设置已生效；若提示重载，先保留检索条件再重载。记录实际改变的站点和权限，方便用户恢复。
5. 若浏览器工具无法操作 Chrome 内部页面，提示用户完成上述两项设置，再继续。组织策略锁定时报告锁定，不声称已经放行。
6. 对已有“无法安全下载”记录，核对它确实是请求的校园知网 PDF，提示用户手工处理 Chrome 的“保留/允许下载”安全提示，再检查下载结果。浏览器安全警告交由用户处理；恶意软件/危险文件告警不能按 HTTP 问题放行。
7. 下载完成后检查下载回执和文件；设置成功不等于 PDF 下载成功。

### 用户选择的校园域通配例外

在环境检查阶段主动帮助完成以下设置，已有有效规则只核实、不重复添加。该规则覆盖河南师范大学的全部子域，允许这些站点显示不安全内容；它不保证解除所有下载拦截，也不用于处理危险文件/恶意软件告警。运行中若仍遇到拦截，再核对具体提示；仅存在 `.crdownload` 文件不足以确定拦截原因。

1. 核对实际校园域名为 `htu.edu.cn`，规则是 **`[*.]htu.edu.cn`**，不是字母顺序相反的 `hut.edu.cn`。其他学校不能套用这条规则。
2. 用户已在当前任务明确授权这项设置时继续执行，不重复请求同一授权；仍遵守当前工具额外要求的确认或浏览器内许可。没有相应授权时，先说明规则范围再询问。
3. 在 Chrome 地址栏输入 `chrome://settings/content/insecureContent`，找到 **“允许显示不安全内容”**（英文可能为 Allowed to show insecure content）。
4. 先检查列表是否已有 `[*.]htu.edu.cn`；已有则核实状态，不重复添加。否则点击该板块的 **“添加”**，输入 `[*.]htu.edu.cn` 并保存。不要添加到“禁止”列表，也不要更改全局默认值。
5. 如工具拒绝 `chrome://` 导航或不能操作内部设置页，给用户上述地址和步骤，由用户在 Chrome 中完成；不要反复重试被拒绝的入口或改用注册表/浏览器配置文件绕过限制。组织策略锁定时报告锁定。
6. 保存后确认规则出现在允许列表；若由用户操作，记录“用户确认设置完成”，不冒称工具已读取设置。回到知网页面，按需重载并复核机构认证与原查询。
7. 先检查原下载是否已恢复或完成；已有文件就核验，不再次点击。旧记录若仍需“保留/允许下载”，交给用户处理。仅在确认失败且无活跃传输时，从原生 PDF 控件重试一次，最后核对实际文件。若仍被拦截，按新的具体提示处理，不能扩大例外或关闭 Safe Browsing。

工具无法操作设置页时，可直接给出：“请在 Chrome 地址栏输入 `chrome://settings/content/insecureContent`，在‘允许显示不安全内容’下点击‘添加’，填写 `[*.]htu.edu.cn` 并保存；已有此规则则无需重复添加。完成后告诉我，我会继续核验校园认证并开始检索。”续跑已有下载时，确认设置后先检查原下载再继续。若页面布局不同，以实际可见标签为准。

官方依据：[Chrome 网站权限](https://support.google.com/chrome/answer/114662)、[Chrome 下载阻止类型](https://support.google.com/chrome/answer/6261569)。当前版本与机构策略可能影响是否提供这些控件。

## 实测下载链路

2026-10-21 在河南师范大学 EasyConnect 环境实测，机构认证正常（页面显示“河南师范大学图书馆”），检索和题录读取均可用。校园知网并非单一主机，至少观察到以下来源：

- `www-cnki-net-s.vpn.htu.edu.cn:8118`：首页。
- `kns-cnki-net-s.vpn.htu.edu.cn:8118`：检索结果与论文详情。
- `navi-cnki-net-s.vpn.htu.edu.cn:8118`：期刊导航。
- `docdown-cnki-net-s.vpn.htu.edu.cn:8118`：详情页“PDF下载/CAJ下载”的中转地址，形如 `/docdown/fulltext/download?q=...`。
- `bar-cnki-net-s.vpn.htu.edu.cn:8118`：结果页下载图标和最终文件地址，形如 `/bar/download/order?id=...`。

据此有两条结论：

1. 下载地址校验来源页。直接在新标签打开 `bar-.../bar/download/order?id=...` 会返回“来源应用不正确(01)”，必须从知网页面内触发下载，不要在地址栏或脚本里单独请求该地址。
2. 权限例外要覆盖实际下载来源。放行 `http://www-cnki-net-s.vpn.htu.edu.cn:8118,*` 的自动下载不覆盖 `docdown-` 与 `bar-` 子域。检查或添加例外时，按本次任务实际观察到的来源站点处理，并记录改了哪些站点。

2026-10-31 使用 Chrome DevTools MCP 1.12.0 补测时，结果表通用“下载”链接被点击后只观察到链接获焦，随后检查未发现新文件或临时传输；不能据此重试同一链接，也不能记为下载已启动。点击题名打开详情页，再点击明确标注的“PDF下载”控件，三篇样本均成功落盘并可解析。该现象是本次工具/页面交互观察，不代表所有知网版本的结果表下载必然失败。若结果表入口没有可确认进度，转到论文详情使用已观察到的 PDF 控件；一次只启动一份，随后检查精确文件、PDF首尾和首页身份，再处理下一份。不要直接在地址栏打开 `bar-.../bar/download/order` 下载链接。

### “未确认”挂起的下载

实测中，从详情页点击“PDF下载”可能不会直接落地为 `.pdf`，而是在下载目录留下 `未确认 <id>.crdownload`：文件内容其实已完整下载（本次两个样本均为 1,328,323 字节、`%PDF-1.6` 开头），但 Chrome 等待用户确认“不安全下载”，该记录也不会出现在下载历史表中。判断方法：文件大小稳定、开头是 `%PDF-`，但扩展名仍是 `.crdownload`。

- 这是 Chrome 的 HTTP 不安全下载确认，不是内容拦截扩展问题（对照“内容拦截扩展”一节）。
- 处理：提示用户在下载气泡中核对来源与文件名，再由用户点击“保留/允许下载”；也可按上面的“用户选择的校园域通配例外”流程处理。之后重新触发并核对落地文件。
- 浏览器工具受 URL 策略限制打不开 `chrome://` 设置页，也不应绕过安全拦截；把该步交给用户，技能本身不代为放行。
- 不要为了消除提示而关闭 Safe Browsing、改注册表或改运行中的 Chrome 配置文件。

## 内容拦截扩展

如果下载页出现 `ERR_BLOCKED_BY_CLIENT` 和“此页面已被 Chrome 屏蔽”，这不是 Chrome 的 HTTP 不安全下载策略，而是内容拦截扩展（如 Adblock Plus）拦截了知网下载子域。实测中 `docdown-cnki-net-s.vpn.htu.edu.cn` 被拦截，而 `bar-cnki-net-s.vpn.htu.edu.cn` 的历史下载成功，说明拦截按域名生效。

- 处理方式是把实际下载子域加入该扩展的允许列表，或在该站点暂停拦截。这是用户的浏览器配置变更，交给用户手工完成，完成后重新触发下载并核对文件。
- 不要代为禁用、卸载或改动拦截扩展的过滤规则，也不要把 `ERR_BLOCKED_BY_CLIENT` 当作 HTTP 下载权限问题去改“不安全内容”设置，两者原因不同。
- 排查时可用只读方式确认根因：下载页正文会显示被屏蔽的主机和 `ERR_BLOCKED_BY_CLIENT`。不要为绕过拦截而关闭 Safe Browsing 或修改浏览器配置文件。

## 节奏与点击

- 一次只启动一篇 PDF。待该篇传输结束或明确失败，再处理下一篇；不要并发下载、预取全部下载链接或反复点击活动任务。
- 连续两篇之间随机等待 3–8 秒；每完成 5 篇随机休息 15–30 秒。用户指定更慢节奏时优先遵从。等待应可中断，继续遵守运行时的时间限制。
- 使用语义按钮点击时直接点已观察到的 `PDF下载` 控件，不为增加随机性而放弃可靠定位。仅当工具支持可见坐标交互、当前截图/布局能确认按钮边界时，可在按钮中央 50% 的内部区域随机选择一点；点击前确认没有遮挡。窗口缩放、滚动或页面变化后重新定位。不得随机点击页面空白或推测坐标。
- 这是串行下载的节奏控制，不能保证不出现验证码。遇到验证码/限流/机构失效立即暂停并交互用户，禁止尝试改变指纹、伪造鼠标轨迹或自动解验证码。
- 每篇保留题名、文件名、实际格式、下载状态和本地路径。PDF 必须能被阅读器/解析器打开并与题名对应，HTML 登录页或 CAJ 不能计入 PDF 成功数。

## 推送 Zotero

用户同时请求 Zotero 时，先验证本地 PDF，再读 [Zotero 流程](zotero.md)。推送脚本优先使用 Zotero MCP，仅在 MCP 写入前不可用时回退 Connector。传入 `pdf_path` 与已核验的题录，禁止传 Cookie 或让 Zotero 辅助脚本重新请求远程 PDF URL。
