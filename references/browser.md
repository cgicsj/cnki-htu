# 浏览器选择与能力检查

仅在任务需要网页操作时执行；已有文件、台账和离线引用转换不启动浏览器或要求 VPN。

1. 按 **腾讯 BrowserSkill → ChatGPT Chrome 插件（`@Chrome`）→ Chrome DevTools MCP** 的顺序检查当前会话实际提供的能力。前一条路线未提供、连接失败或缺少当前步骤所需能力时，记录原因再检查下一条；不能因后续工具已配置而跳过优先项。不猜测工具 API。
2. 核实所选工具可以读取实际任务页面，并沿校园入口确认 VPN 路线和知网机构认证。BrowserSkill 的 Agent Window 不等同于用户当前标签；其他路线也须按其当前说明确认实际控制的窗口/标签。Windows 的 `check_environment.ps1` 仅报告优先级和本地环境信号，不检测浏览器技能、CLI、扩展或 MCP 是否已连接，也不证明认证成功。
3. 明确区分工具未提供、连接失败、能力不足与认证失效。登录、验证码、用户介入、借用拒绝或权限确认须在原路线处理，不能通过回退绕过。没有合适的本地浏览器连接时保存进度并报告所缺能力。不自动安装扩展、开启 Developer mode / full CDP、改变系统默认浏览器或启动其他浏览器；所选工具按自身文档创建任务窗口属于正常会话流程。若使用 full CDP，遵循运行时的显式授权要求。
4. 需要登录时由用户在实际连接的 Chrome 会话中完成；不同会话的登录结论不能互用，不导出或复制 Cookie 等浏览器凭据。
5. 实际连接的 Chrome 会话必须能沿校园入口访问并核验机构认证，才执行需要机构权限的步骤。导航、下载、权限与验证码处理遵循当前工具的规则。

任务访问记录补充 `browser_tool`（实际工具名称或 unavailable）、所选实例/会话、连接状态和各优先项的检查结果/回退原因；已有记录中的 `browser_skill` 作为历史字段保留，不据此跳过当前工具检查。所有校园路径、页面和文件完成证据仍按原有访问与下载流程记录。

## BrowserSkill 接入

- 优先检查当前提供的 BrowserSkill MCP（如 `mcp__browser_skill`）及已安装的 `browser-skill` 技能。使用 MCP 时读取工具当前说明；使用 CLI 时先读取该技能的 `SKILL.md` 及本步骤要求的协作、标签/实例、下载等参考。两种接入方式的会话可见性和参数可能不同，不混用 session、tab、context 或元素引用。
- 按实际接入方式启动会话，在选定的本地实例中使用 Agent Window；需要指定浏览器实例时先核实映射，不猜测 profile 名与实例 ID 的对应关系。已有用户标签必须按文档先列出、再借用；不重复待确认、拒绝、超时或结果不明的借用，不换工具接管同一标签以绕过确认。
- 导航后先同步并读取页面，再操作观察到的控件。MCP 使用返回的 `context_id` 与 VOM 引用；CLI 使用同步返回的 context 和当前 refs，额外 observation/expect 要求遵循其当前文档。用户介入后等待交还并重新同步，不复用旧控制凭证。工具完成不等于检索或下载已成功，仍核对业务结果。
- 网站读写仅使用当前接口实际支持的能力。页面脚本、扩展、CLI 或 MCP 的存在不证明可下载、可操作 `chrome://` 或可接管所有标签；缺少能力时按优先级回退，确认待处理或结果不明时先核对，不重发操作。借用、会话清理及归还标签遵循当前文档；CLI 会话结束时使用 `bsk session stop <id>`，不重启共享 daemon。

## 页面操作与恢复

- BrowserSkill、ChatGPT Chrome 插件与 Chrome DevTools MCP 的连接和操作能力可能不同，按优先级及本步骤所需能力选择。切换前保存台账，确认没有活跃传输、待确认操作或结果不明的写入；切换后重新观察页面和机构认证，不复用旧标签编号、元素引用或控制凭证，不复制 Cookie 来迁移登录。
- 默认采用无截图操作：优先用 BrowserSkill 的 VOM、当前页面的 accessibility/DOM snapshot 或工具允许的 DOM 状态读取控件和文本，再用当前浏览器工具提供的原生控件接口操作并刷新状态核验。常规导航、填表、检索和结果核验不主动截图；仅当页面可见性、遮挡或纯图形状态无法从结构信息确认，或运行时要求视觉证据时截图。截图调用卡顿或失败后不要反复重试；改用结构信息核验，仍无法确认时报告具体的不确定点。
- 页面异步加载后，旧 snapshot 引用可能过期。等待目标控件/状态出现，再刷新定位；只对当前观察到的控件操作，避免预设“一个脚本必定完成”。检索建议遮挡控件时先正常关闭建议列表，再操作后续控件。
- 预期新标签时，如工具支持，先监听再点击；未收到弹窗回执时先检查本次操作打开的标签及当前页。校园页面的 DOM href 可能指向公网，而实际点击会经校园代理：优先实际控件，不把重放 href 当作必然保留认证。只有已观察并确认访问路线的链接才用于当前页导航，导航后重验机构状态。
- 原生点击超时或截图不可用时，先检查窗口、页面、覆盖层与操作结果。工具允许时，可对已观察到、当前可见的页面控件使用 DOM 事件回退，并记录该执行方式；不得移除 readonly、强制显隐控件或直接调用未公开的站点内部函数。viewport 为零且无法核实可见目标时暂停交互；可继续独立离线工作。
- 验证码按当前可见状态判断：仅在快照中找到“安全验证”文字，不足以证明出现或遮挡；预加载组件可能位于屏幕外或尺寸为零。可见性不明时先查看当前截图；截图未显示挑战时不得声称“页面显示验证码”，继续操作页面上可用的控件。只有截图确认挑战可见且阻挡操作时才交给用户。不能绕过验证，也不能把验证阻碍或页面错误计作零条文献。
- 浏览器重启/连接丢失后，从台账和冻结文献集合恢复，重新识别实际标签与认证，不复用旧标签编号。单项连续两次无进展时记录阻碍，避免反复点击。
