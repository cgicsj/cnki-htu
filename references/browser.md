# 浏览器选择与能力检查

仅在任务需要网页操作时执行；已有文件、台账和离线引用转换不启动浏览器或要求 VPN。

1. 检查当前 agent 提供的浏览器能力；Codex Chrome 插件可用时，优先用 `@Chrome` 连接用户本地 Chrome 会话并遵循其当前工具说明。插件不可用或不能接入时，再检查 Chrome DevTools MCP 等已提供工具；只有能接入用户本地 Chrome 会话的工具才可用于该路线。不猜测工具 API。
2. 核实所选工具可以列出或读取实际 Chrome 标签，并沿校园入口确认 VPN 路线和知网机构认证。Windows 的 `check_environment.ps1` 只提供本地环境信号，不能检测浏览器插件/MCP 是否可用，也不能证明连接或认证成功。
3. 明确区分插件或 MCP 未提供、连接失败与认证失效。按当前工具说明诊断；没有可用的本地 Chrome 连接时保存进度并报告所缺能力。不自动安装插件、开启 Developer mode / full CDP、改变系统默认浏览器或启动其他浏览器。若使用 full CDP，遵循运行时的显式授权要求。
4. 需要登录时由用户在实际连接的 Chrome 会话中完成；不同会话的登录结论不能互用，不导出或复制 Cookie 等浏览器凭据。
5. 实际连接的 Chrome 会话必须能沿校园入口访问并核验机构认证，才执行需要机构权限的步骤。导航、下载、权限与验证码处理遵循当前工具的规则。

任务访问记录补充 `browser_tool`（实际工具名称或 unavailable）、选择原因和实际连接状态；已有记录中的 `browser_skill` 作为历史字段保留，不据此跳过当前工具检查。所有校园路径、页面和文件完成证据仍按原有访问与下载流程记录。

## 页面操作与恢复

- Codex Chrome 插件与 Chrome DevTools MCP 的连接和操作能力可能不同，先核对当前实际提供的能力。连接成功也可能只是新建的独立 Chrome 会话；以当前标签和机构名确认是否连接到已登录会话，不复制 Cookie 来迁移登录。
- 默认采用无截图操作：优先用当前页面的 accessibility/DOM snapshot 或 full CDP 暴露的 DOM 状态读取控件和文本，再用当前浏览器工具提供的原生控件接口操作并刷新状态核验。常规导航、填表、检索和结果核验不主动截图；仅当页面可见性、遮挡或纯图形状态无法从结构信息确认，或运行时要求视觉证据时截图。截图调用卡顿或失败后不要反复重试；改用结构信息核验，仍无法确认时报告具体的不确定点。
- 页面异步加载后，旧 snapshot 引用可能过期。等待目标控件/状态出现，再刷新定位；只对当前观察到的控件操作，避免预设“一个脚本必定完成”。检索建议遮挡控件时先正常关闭建议列表，再操作后续控件。
- 预期新标签时，如工具支持，先监听再点击；未收到弹窗回执时先检查本次操作打开的标签及当前页。校园页面的 DOM href 可能指向公网，而实际点击会经校园代理：优先实际控件，不把重放 href 当作必然保留认证。只有已观察并确认访问路线的链接才用于当前页导航，导航后重验机构状态。
- 原生点击超时或截图不可用时，先检查窗口、页面、覆盖层与操作结果。工具允许时，可对已观察到、当前可见的页面控件使用 DOM 事件回退，并记录该执行方式；不得移除 readonly、强制显隐控件或直接调用未公开的站点内部函数。viewport 为零且无法核实可见目标时暂停交互；可继续独立离线工作。
- 验证码按当前可见状态判断：仅在快照中找到“安全验证”文字，不足以证明出现或遮挡；预加载组件可能位于屏幕外或尺寸为零。可见性不明时先查看当前截图；截图未显示挑战时不得声称“页面显示验证码”，继续操作页面上可用的控件。只有截图确认挑战可见且阻挡操作时才交给用户。不能绕过验证，也不能把验证阻碍或页面错误计作零条文献。
- 浏览器重启/连接丢失后，从台账和冻结文献集合恢复，重新识别实际标签与认证，不复用旧标签编号。单项连续两次无进展时记录阻碍，避免反复点击。
