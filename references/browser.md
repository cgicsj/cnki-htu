# 浏览器选择与能力检查

仅在任务需要网页操作时执行；已有文件、台账和离线引用转换不启动浏览器或要求 VPN。

1. 检查当前 agent 的工具清单，优先使用 `chrome-mcp`，读取其当前工具说明并连接用户本地 Chrome 会话。服务器或工具名称以当前环境实际提供的名称为准，不猜测工具 API。
2. 核实工具可以列出或读取实际 Chrome 标签，并沿校园入口确认 VPN 路线和知网机构认证。Windows 的 `check_environment.ps1` 只提供本地环境信号，不能检测 agent 的 MCP 工具是否可用，也不能证明连接或认证成功。
3. `chrome-mcp` 缺失或连接不可用时，明确区分工具未提供、连接失败与认证失效，按当前工具说明诊断。只有其他已提供的工具能够连接用户本地 Chrome 并重新核验校园认证时才回退；没有可用连接时保存进度并报告所缺能力。不自动安装工具、更改系统默认浏览器或启动其他浏览器。
4. 需要登录时由用户在实际连接的 Chrome 会话中完成；不同会话的登录结论不能互用，不导出或复制 Cookie 等浏览器凭据。
5. 实际连接的 Chrome 会话必须能沿校园入口访问并核验机构认证，才执行需要机构权限的步骤。导航、下载、权限与验证码处理遵循当前工具的规则。

任务访问记录补充 `browser_tool`（实际工具名称或 unavailable）、选择原因和实际连接状态；已有记录中的 `browser_skill` 作为历史字段保留，不据此跳过当前工具检查。所有校园路径、页面和文件完成证据仍按原有访问与下载流程记录。
