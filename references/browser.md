# 浏览器选择与能力检查

仅在任务需要网页操作时执行；已有文件、台账和离线引用转换不启动浏览器或要求 VPN。

1. 先查看当前 agent 的可用技能清单，查找名称为 `ego-browser` 的技能。已列出时，读取其实际 `SKILL.md` 并遵循其中的初始化与工具说明，优先使用 ego-browser。技能要求执行 `ego-browser skill` 时，先运行并读完动态使用指南；不要照搬其他版本的浏览器 API。
2. 若清单中没有，检查 agent 配置的技能目录（例如项目 `.agents/skills`、用户 `~/.agents/skills`、`~/.codex/skills`，以及当前 agent 明确使用的其他目录）。存在可读的 `ego-browser/SKILL.md` 时读取并核实工具能力。不要硬编码某台电脑的用户名或安装路径。Windows 的 `check_environment.ps1` 可提供候选路径及 CLI 存在信号，不能代替技能读取或浏览器连接验证。
3. 已安装则优先连接 ego-browser 中用户的本地会话，核验校园页面与机构认证；Chrome 的 Cookie、VPN 页面和标签不会自动转移到 ego-browser。需要登录时由用户在该浏览器完成，不导出或复制浏览器凭据。
4. 未安装 ego-browser 时，使用当前环境支持且已认证的本地 Chrome 工具，并读取对应工具说明。已安装但 CLI/连接不可用时先做技能文档允许的诊断；仍不可用则说明原因，仅在能核验本地 Chrome 校园访问时回退，不把连接失败描述成未安装。无需为此自动安装、升级技能或更改全局浏览器。
5. 所选浏览器必须能沿实际校园入口访问并核验机构认证，才执行需要机构权限的步骤。两种浏览器都不可用时保存进度并报告所缺能力。导航、下载、权限与验证码处理遵循当前工具的规则。

任务访问记录补充 `browser_skill`（ego-browser / chrome / unavailable）、选择原因和实际连接状态。所有校园路径、页面和文件完成证据仍按原有访问与下载流程记录。
